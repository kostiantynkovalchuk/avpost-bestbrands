# AV Post — правила вёрстки и работы над выпусками

Свод правил, выведенный из реальных проблем при вёрстке Выпусков №1–2.
Читать перед началом каждого нового выпуска. Не переоткрывать решённые вопросы.

---

## 1. Архитектура выпуска

- Один выпуск = один самодостаточный `index.html`, все изображения inline base64.
- Билингва UA/RU: `<span class="t" data-ua data-ru>` + `setLang()`. Весь видимый текст — только через этот механизм.
- Mobile-first: base <768 / tablet ≥768 / desktop ≥1024.
- URL-схема: `/` → 307 → свежий выпуск; старые выпуски живут по `/issue-N/`; `vercel.json` в корне.
- Деплой: push в `main` → Vercel auto-deploy.

## 2. Главное правило про изображения (стоило больше всего итераций)

**CSS не может «отдалить» кадр, если base64 в файле уже обрезан.**
Если правка `object-position` / высоты контейнера дважды не дала эффекта —
проблема не в селекторах, а в исходнике. Лечится только заменой `src`.

- Перед вёрсткой секции проверять ориентацию исходника.
  **Вертикальное фото в широком hero-контейнере не работает** — всегда либо
  обрезка лиц, либо гигантская высота. Решения по приоритету:
  1. заменить на горизонтальный кадр (павлины);
  2. дуэт: два вертикальных фото side-by-side в одной figure (Frizzante);
  3. крайний случай — contain + blur-подложка (не использовали, выглядит стоково).
- Кодировать в файл сразу финальный кадр. Кроп делать в исходнике, не в CSS.
- Full-bleed по ширине меняет и вертикальный кроп — после расширения
  перепроверить `object-position` (картинг: вылезли шины).
- Коллажи из двух кадров — резать до нужной половины в исходнике
  (pet_horaichuk, pet_volodko, мем 2).

## 3. Правки по брейкпоинтам

- **Утверждённый брейкпоинт заморожен.** Если мобилка approved — её разметку,
  base64 и стили не трогаем вообще. Десктоп-вариант делается параллельным
  элементом: новый блок `display:none` по умолчанию, `display:...` в
  `@media (min-width:1024px)`; старый — `display:none !important` на десктопе.
- Все desktop-правки — только в одном блоке `@media (min-width:1024px)`
  в конце `<style>`, с `!important`. Инлайновые мобильные стили не редактировать.
- После любой правки — регрессионный скриншот мобилки (390px) затронутых
  секций: подтверждение пиксельной идентичности.
- Скриншоты проверки: desktop 1280px, mobile 390px.

## 4. Диагностика перед повторной правкой

- Если правка «не применилась» — не повторять вслепую. Сначала шаг 0:
  открыть файл, сверить селектор с реальной разметкой, проверить, не
  перебивает ли inline-стиль. В отчёте агента: какой селектор был, какой
  стал, почему не работал.
- Три одинаковых «не сработало» подряд = общая причина (не тот селектор
  или обрезанный исходник), а не три отдельных бага.

## 5. Работа с Replit-агентом

- Задание — только текстом в императиве: «ВЫПОЛНИ…, не спрашивай
  подтверждения». Файлы-вложения агент читает как «справку» и не выполняет.
- Один промпт = связанный пакет правок; чужие секции явно помечать
  «НЕ трогать» (правка заголовков «Легенды» не должна цеплять другие
  нумерованные списки — прописывать blast radius явно).
- Git: commit + `git commit --amend --reset-author` + push. «Лишние»
  коммиты в истории — норм.
- Новые фото/мемы для замены — в Replit `/tmp/`; исходники выпуска —
  Google Drive «Корпоративная газета».
- Агент обязан прикладывать скриншоты результата (1280 / 390) к отчёту.

## 6. Контент и язык (не переоткрывать)

- «бренді», никогда «коньяк» (законодательство Украины).
- Имена по языкам: «Пустовіт» в UA / «Пустовит» в RU. «Олія Боярко» —
  именно «Олія» (подтверждено).
- Весь RU — перевод, требует вычитки перед рассылкой. Зоны риска:
  разговорные цитаты, гороскоп, подписи stats.
- Мемы остаются на украинском в обеих версиях, не переводить.
- Подписи можно удалять только осознанным решением (3 фото Мотивации —
  удалены намеренно).

## 7. Утверждённые паттерны разметки

- Нумерованные списки «кружок + текст»: на десктопе — одна колонка,
  порядок 1-2-3-4-5 сверху вниз. Двухколоночная раскладка ломает порядок.
- Списки/колонки выравнивать по верху — без «провалов» перед блоком
  в одной из колонок.
- «Легенда офісу»: зигзаг текст/мем (desktop), CSS-counter кружки,
  заголовок пункта над описанием. Мем N = файл N (1.png…7.png).
- Карусель питомцев: mobile 82% flex-basis, tablet 38%, desktop 27%,
  стрелки ≥768, счётчик N/15.
- Stats-значения типа «~1 рік» — одна строка (`white-space:nowrap`,
  при раздельной разметке — объединить).
- Портреты в парных карточках (Герої полів) — одинаковая высота
  контейнеров, кадрирование лиц сопоставимое (`object-position: center top`).
- Фото-сетки: между фото всегда белый gap, значение — как в остальных
  секциях выпуска (не выдумывать новое).

## 8. Отвергнутые решения (не предлагать заново)

- Turn.js (page-flip) — отвергнут.
- Masonry для мемов — отвергнут (используется зигзаг).
- Full-width карточки карусели на мобильном — отвергнуто
  (проблемные фото решены обрезкой коллажей).

## 9. Финализация выпуска

1. Десктоп-полировка по списку → проверка на 1280px.
2. RU-вычитка сверху вниз, правки списком «секция → фраза → как надо».
3. Скрин-тест на целевых устройствах.
4. Рассылка: ссылка на корень (`avpost-bestbrands.vercel.app`) —
   корень всегда указывает на свежий выпуск.
